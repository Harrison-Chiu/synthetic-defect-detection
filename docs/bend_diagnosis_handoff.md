## 2. 已經「證偽」的假設（重要：請勿重繞這些路）

接手時最容易浪費時間的，就是重新提出這些已經被資料排除的解釋。逐一列出與證偽依據：

1. **「訊號被下採樣吃掉 / bend 只改 1–3px」——已證偽。**
   證據：FIG A（normal vs defect 差異熱圖疊加，az=0 el=30 同 pose）顯示 **bend_heavy 的差異是全圖最強的**，整個螺絲頭和身都泛紅泛黃，比 displace、remesh 都明顯。原文件「身約 50px、bend 只改 1–3px」是低估/誤判（使用者確認 bend_heavy 程度不小，且該圖是角度校正前的，校正後差異會更大）。

2. **「class imbalance 導致 bend 學不到」——基本排除。**
   bend_heavy 的缺陷像素面積不小（見 FIG A）。整體 imbalance（defect 僅 5.3%）確實存在且已由 S3 改用 Dice+BCE 大幅緩解（defect IoU 0.004 → 0.362），但它無法單獨解釋為何「同樣是缺陷、面積也夠」的 bend 遠輸 remesh/displace。

3. **「物理天花板（bend 本質學不到）」——已證偽，且這是個危險說法。**
   差異肉眼可見得不得了（FIG A），不存在「看不到所以學不到」。此說法的危險在於把「可能可解的問題」重新定義成「不可解的客觀限制」，導致停止追究。**請主動抵抗這種收尾方式。**

> **方法論提醒**：原始 handoff §7 把大量篇幅放在「多頭為什麼退步」（一個已被否決、不影響最終模型的 ablation），卻用「物理天花板」一句話帶過 bend 這個真正的核心失敗。這是「注意力放錯地方」的典型。接手時請把焦點鎖在 bend，不要被多頭的討論帶走。

## 3. 目前最強假設：label 粒度與缺陷視覺本質不匹配

**使用者口述的 S3 label 規則（待用 repo 程式核實）**：

- Head1（part/bg）：標哪些像素是零件、哪些是背景。
- Head2（defect）：**以「整顆零件」為單位**——只要一顆零件有瑕疵，**整顆**都被標成 defect 色；正常零件標成另一色。

**若上述規則屬實，bend 低分的因果解釋如下：**

- 對 **remesh / displace**：視覺變化**佈滿整顆零件表面**（FIG A 的紅點散在整根螺絲上）。label 說「整顆是缺陷」，影像也「整顆都看得出不一樣」→ 監督訊號**自洽** → 學得起來。
- 對 **bend**：視覺差異**高度集中在彎折處與輪廓邊緣**，而螺絲身內部像素**跟正常幾乎一樣**。label 卻要模型把**整顆（含與正常無異的內部像素）**都標成 defect → 模型被要求「把看起來正常的像素硬學成 defect」→ 做不到 → recall 崩到接近 0。

**這一個假設同時解釋了三件事**（強度來自三方佐證）：
1. 為何 bend 最低、remesh 最高（label 規則對三者的「公平性」天差地遠）。
2. 為何 bend「訊號最強卻最學不到」（矛盾不在訊號側，在監督側）。
3. 為何訓練曲線的 defect IoU 在啟動後（epoch 12+）**劇烈震盪於 0.2–0.33**、始終不收斂（模型在「跟著影像走」與「跟著 label 走」之間反覆橫跳，典型的監督訊號矛盾現象）。

**精確版結論**：問題不是 mask「標錯位置」，而是**標註粒度（整顆 vs 實際變形區）與缺陷視覺本質不匹配**，且此不匹配對 bend 最致命、對 remesh 最無害。「整顆標記」這種做法其實把 classification 語意混進了本該是 segmentation 的監督。

## 5. 給 Claude Code 的查證目標（按優先序）

**【第一優先】找出 defect mask 的生成程式，確認標註粒度。**
- 去 repo 找 defect mask 是怎麼生成的：哪個檔、依據什麼規則。候選位置：composite 階段的 mask 合成邏輯、`src/schema.py`、資料生成 notebook。
- 要回答的具體問題：**defect mask 是「整顆零件 fill」還是「逐像素標實際偏離正常的區域」？** 依據是幾何變形量、深度差、還是「這顆零件 flag=defect 就整顆塗」？
- 若確認是「整顆塗」→ §3 假設成立，根因鎖定。

**【第二優先】把 bend_heavy 的 defect mask 疊在原圖上目視。**
- 不是看影像差異圖（FIG A 已知差異很強），是看 **label 側標在哪**。
- 預期（若假設成立）：mask 會把整顆螺絲塗滿，包括與正常無異的螺絲身內部，而非只標彎折/邊緣的視覺變形區。

**【若上述證實，可評估的解法方向（先別急著實作，先敲定根因）】**
- 把 defect mask 從「整顆」改成「實際偏離正常的像素」（純 segmentation 監督）。合成資料的特權：可用 normal vs defect 的幾何/深度/影像差異自動生成 per-pixel mask，不需人工標。
- 這是「用資料解」而非「用 loss/架構解」，最直接、最符合「掌握每個環節」的目標。

## 6. 流程紀律（沿用，避免重蹈 S4 覆轍）

- **以 S3 為唯一基準。** S4 best 的四項資料修正（bend 軸對齊、HDRI 2→4、同場景 HDRI 統一、remesh octree 加粗）若要併回，**一項一項併、單獨驗證**，不要四項一起上——否則無法歸因是哪一項起作用（這正是 S4 best 的缺陷：變因混在一起）。
- **任何「為什麼」的解釋，沒有對照實驗就標為推測，不寫進結論。**（沿用原 handoff §7 的事實/推測分離紀律。）
- **抵抗「物理天花板」式的提前結案。** 看到低分先問「這個分數到底在量什麼、label 是否自洽」，再問「模型/架構問題」。

## 7. 補充背景（合成資料的定位）

訓練結果**不會實際部署**，目的是**學習如何訓練模型、判斷失敗的因果**。因此：
- 不需處理 sim-to-real gap。
- 「合成數值簽名」風險（模型可能學 remesh 的渲染簽名而非「形變」語意）值得留意，但**不是當前主線**——當前主線是 bend 的 label 矛盾。
- 評估標準是「因果鏈是否清楚、假設是否被乾淨地證實或證偽」，不是 defect IoU 的絕對值。
